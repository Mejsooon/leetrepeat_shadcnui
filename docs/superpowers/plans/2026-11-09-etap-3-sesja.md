# LeetRepeat v3 — Etap 3: Sesja — plan implementacji

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Użytkownik przechodzi sesję powtórek: rozwiązuje zadanie w edytorze, uruchamia testy, ocenia (Znowu / Trudne / Dobre / Łatwe), a aplikacja zapisuje ocenę i planuje kolejny termin.

**Architecture:** Backend: reguły harmonogramu, kolejka sesji i zapis oceny w `backend/services/scheduler.py`, SQL w `backend/repository/reviews.py`, endpointy `/session`, `/run`, `/tasks/{id}/review-preview`, `/tasks/{id}/review` w `routes.py`, blokada żądań z obcych stron w `main.py`. Frontend: strona `Sesja.tsx` trzyma kolejkę, fazę (rozwiązywanie / ocena) i stoper; widoki to `SolvePanel.tsx` i `RatingPanel.tsx`, wyniki testów to `TestResults.tsx`; daty liczone w czasie lokalnym (`lib/dates.ts`).

**Tech Stack:** jak w Etapie 2 + komponenty shadcn/ui `tabs`, `radio-group` (kopiowane z `/tmp/shadcn-src/ui/apps/v4/registry/new-york-v4/ui`, a gdy go nie ma — z GitHub `shadcn-ui/ui@8ab2771`).

**Spec:** `docs/superpowers/specs/2026-11-08-leetrepeat-v3-design.md` (sekcje 2, 3 `reviews`, 4, 5, 6 „Sesja”, „Skróty”, „Notatki”, „Obsługa błędów”, 8, 9 pkt 3). Wygląd: artboardy `Rozwiazywanie-blad`, `Rozwiazywanie-ok`, `Ocena` w `/home/claude/lr-canvas/project/*.dc.html`.

## Global Constraints

- Wszystko z Etapów 1–2 nadal obowiązuje: `127.0.0.1:8000`, offline, `frontend/dist` commitowany (`npm run build` przed commitem zmian frontendu), teksty i komentarze po polsku, prosty liniowy kod.
- Oceny w API: `again` │ `hard` │ `good` │ `easy`; etykiety: Znowu / Trudne / Dobre / Łatwe; klawisze `1`–`4` w tej kolejności.
- Harmonogram (spec §4): zadanie z `interval_days == 0` → again 0, hard 1, good 3, easy 7; w pozostałych przypadkach → again 0, hard `max(odstęp × 1,2; odstęp + 1)`, good odstęp × 2,5, easy odstęp × 3,5. `due_date = dziś + floor(odstęp + 0,5)` dni (zaokrąglenie „w górę od połowy”, nie bankierskie `round`). Odstęp zapisywany jako REAL bez zaokrąglania.
- Kolejność sesji: najpierw Do powtórki (`due_date` rosnąco, potem `id`), potem Nowe (`created_at` rosnąco, potem `id`). W nauce / Utrwalone nie wchodzą.
- Czas rozwiązania = od wyświetlenia zadania (po wczytaniu) do kliknięcia „Zapisz ocenę”, w pełnych sekundach.
- Edycja zadania nadal nigdy nie zmienia harmonogramu; harmonogram zmienia wyłącznie `POST /tasks/{id}/review`.
- Daty `YYYY-MM-DD` we frontendzie zawsze w czasie lokalnym (nigdy `toISOString()` do liczenia „dziś”).
- Ustawienia runtime’ów (Etap 5) jeszcze nie istnieją: `/run` woła `run_tests` z wartościami domyślnymi.
